# CS2 自定义音乐盒(v0.8.1)

用你自己导入的音乐,替代 CS2 游戏内音乐盒(Music Kit)。

> **第一次用?** 看图文版 **[新手教程](docs/新手教程.md)**。程序第一次打开时也会自动显示新手教程页面,每做完一步自动打勾,还能「模拟一局」——不开游戏先听整局效果。
不改游戏文件、不注入进程,只使用 Valve 官方的 **游戏状态集成 GSI(Game State Integration)**。

## 原理

```
CS2 ──(GSI:回合阶段/炸弹/胜负/MVP…  HTTP POST)──▶ 本程序(127.0.0.1:31777)
                                                    │ 事件引擎:比对前后状态 → 生成事件
                                                    ▼
                                         播放你为该事件设定的音乐片段
```

因为只是本地播放声音,不需要叠加层(Overlay),**独占全屏(Exclusive Fullscreen)也能用**。

## 快速开始(Windows)

1. 两种运行方式选一个:
   - **exe 版(推荐给普通玩家)**:下载 `CS2MusicBox-windows.zip`,解压到任意文件夹(不要放进 Program Files),双击 `CS2MusicBox.exe`。不需要装 Python。怎么打包见下文「打包成 exe」
   - **源码版**:安装 Python 3.9 以上(python.org,安装时勾选 *Add Python to PATH*),双击 `start.bat`(首次会自动安装依赖 `pygame-ce` 和 AI 分析用的 `librosa`);也可以手动 `pip install -r requirements.txt` 然后 `python main.py`
2. 程序会自动找到 CS2 的 cfg 目录,写入 `gamestate_integration_musicbox.cfg`
   - 日志里出现「需要重启 CS2 才生效」→ **重启一次 CS2**
   - 没找到目录 → 在面板「设置」页手动填写,例如
     `D:\SteamLibrary\steamapps\common\Counter-Strike Global Offensive\game\csgo\cfg`
3. 浏览器会自动打开控制面板 `http://127.0.0.1:31777`(第一次会先显示新手教程,右上角「教程」随时回来),有六页:
   - **音乐盒**:13 个事件按一个回合的先后排成「线路图」(大厅 / 回合 / 炸弹 / 终局四条轨道)。点任意站点在右侧设置它的音乐;**改动自动保存**
   - **剪辑台**:导入歌曲,在波形上选片段、试听、导出,一键用在某个站点(见下文)
   - **AI 推荐**:自动分析段落并推荐片段
   - **社区**:分享自己的音乐盒、导入别人的(见下文)
   - **队友语音**(实验性功能):把你的麦克风和音乐混在一起送进游戏语音,队友也能听到(见下文)
   - **设置**:CS2 连接、计时微调、日志
   - 顶栏中间是仿游戏 HUD 的状态:对局中显示比分和估算的回合时间,下包后变成红色炸弹倒计时;游戏事件发生时右上角会滑出提示
4. 关掉游戏自带的音乐:进游戏后在控制台输入 `exec musicbox_mute`
   (只把各类“音乐”音量设为 0,枪声、脚步不受影响;想恢复就到 设置 > 音频 > 音乐 调回滑块)

**不开游戏先试效果**:在「音乐盒」页底部或新手教程里点「模拟一局」,会模拟一整局比赛(约 1 分钟,顶栏显示「模拟」)。源码版也可以另开终端运行 `python simulate.py`。

## 队友语音:让队友也听到你的音乐(v0.8 新增 · 实验性功能)

> **实验性功能(experimental)**:还没有在真实的 Windows + CS2 环境里充分验证,可能遇到声音断续、没声音、设备认不出来等问题。遇到问题直接关掉它,不影响其他功能。欢迎反馈。
>
> **需要用户自己下载 VB-CABLE**:本程序不附带、也不会自动安装这个虚拟声卡驱动(它是 VB-Audio 的捐赠软件,安装驱动需要管理员权限)。

```
你的真实麦克风 ─┐
                ├─▶ 本程序混音(你说话时自动压低音乐)─▶ CABLE Input ══ VB-CABLE 虚拟线 ══▶ CABLE Output ─▶ Steam / CS2 语音 ─▶ 队友
正在放的音乐 ───┘
你的耳机:照常听音乐,和以前一样
```

程序自己做不出一个“麦克风设备”(那需要 Windows 内核驱动),所以借助免费的**虚拟声卡 VB-CABLE**(virtual audio cable)当中转,需要你自己下载安装。本程序负责混音(mixing),游戏把虚拟声卡当麦克风用。

**设置(只做一次)**
1. 自己下载安装 VB-CABLE:[vb-audio.com/Cable](https://vb-audio.com/Cable/) 下载,解压后右键 `VBCABLE_Setup_x64.exe` →「以管理员身份运行」→ Install,**装完重启电脑**
2. 面板「队友语音」页 → 打开「把音乐播给队友」。麦克风选你平时用的那个,「送到」保持自动(CABLE Input)
3. Steam → 设置 → 语音 → 语音输入设备(Voice Input Device)选 **CABLE Output (VB-Audio Virtual Cable)**。CS2 的 设置 › 音频 里如果有「语音输入设备」,也选它
4. 进游戏照常按说话键。想先确认效果:在 Steam 语音设置里点「开始麦克风测试」,同时在面板点「发送测试」,听到的就是队友听到的

**功能**
- **闪避(ducking)**:你说话时音乐自动压低(默认 12 dB),说完 0.4 秒后恢复,报点不会被音乐盖住
- **说话检测**:麦克风电平表上有阈值标记,拖滑块调到“说话时超过、安静时低于”的位置;**噪声门(noise gate)** 可选,不说话时关掉麦克风(开放麦时有用)
- **选择哪些站点放给队友**,有「只放庆祝时刻」(回合胜利、MVP、比赛胜利)预设;队友听到的音乐音量单独调,不影响你自己听到的
- 面板里的试听**不会**送给队友;「发送测试」只送给队友 8 秒,你自己听不到
- **防回声**:虚拟设备不能被选成麦克风(否则会自己录自己)
- 中途打开时,正在放的音乐会从当前位置接上;顶栏有小标记显示「队友在听」
- 麦克风到队友的额外延迟约 100 毫秒(输出缓冲 60 毫秒,避免断音)

**注意**
- 用按键说话(push-to-talk)时,只有按住说话键队友才听得到,音乐也一样。程序不会替你按键(不向游戏发送任何输入)
- 队友可以把你静音;一直往语音里放音乐,可能被举报「语音骚扰」导致暂时不能用语音。建议只在回合结束、MVP 这类时刻放
- 用耳机,不要用外放(否则麦克风会录到游戏声音);不要把 Windows 默认播放设备设成 CABLE Input(否则电脑上所有声音都会进语音)
- 和 Discord、Voicemeeter 这类软件一样,只是处理音频设备,不读写游戏内存、不注入游戏
- 测试情况:用 PulseAudio 虚拟设备模拟了整条链路(假麦克风 → 混音 → 虚拟线 → 录音分析),说话检测、压低 12 dB、站点过滤、试听不外泄、测试发送都验证过;真实 Windows + VB-CABLE + CS2 还需要你实际试一下

## 打包成 exe(v0.7 新增)

打包后的程序是一个文件夹:`CS2MusicBox.exe` + `_internal`(Python、librosa 等全部依赖)+ `使用说明.txt`,解压即用,别人电脑上不需要装 Python。约 250–350 MB(主要是 AI 分析用的 numba/LLVM 和 scipy),zip 后一百多 MB。

**方式 1:用 GitHub 自动打包(不需要自己的打包环境)**
项目里的 `.github/workflows/build-exe.yml` 会在 GitHub 的 Windows 机器上打包,并自动测试打出来的 exe(启动、AI 分析、重复启动检测):
- 手动:仓库 → Actions → *Build Windows exe* → Run workflow,完成后在这次运行的 Artifacts 里下载 `CS2MusicBox-windows.zip`
- 发版:`git tag v0.7.0 && git push origin v0.7.0`,会自动创建 Release 并附上 zip,直接把 Release 链接发给朋友

**方式 2:在自己的 Windows 电脑上打包**
装好 Python 3.13 后双击 `build_exe.bat`。它会建一个独立的打包环境 `.venv-build`、按 `requirements-exe.txt` 安装固定版本的依赖、运行 PyInstaller、跑冒烟测试,最后生成 `dist\CS2MusicBox-windows.zip`。

**exe 版的行为**
- 数据(配置、曲库、分析缓存、社区登录)放在 exe 旁边;那个文件夹不能写入时(比如放在 Program Files)改放 `%LOCALAPPDATA%\CS2MusicBox`。升级时用新的 exe 和 `_internal` 覆盖即可,数据保留
- 黑色控制台窗口就是日志,关掉它就退出程序;程序已在运行时再双击,会直接打开控制面板而不是报端口占用
- 第一次 AI 分析会慢十几秒(numba 编译),编译结果缓存在 `%LOCALAPPDATA%\numba`,之后就快了
- 没有代码签名证书,首次运行 Windows SmartScreen 可能提示「已保护你的电脑」→「更多信息」→「仍要运行」。偶尔有杀毒软件误报 PyInstaller 程序,可以加白名单

打包配置在 `packaging/`:`cs2musicbox.spec`(PyInstaller 配置,onedir 模式启动更快、更少误报)、`icon.ico`、`version_info.txt`(文件属性里的版本)、`smoke_test.py`。

## 自动检测游戏进程(v0.6 新增)

GSI 只在游戏活着时推送数据,游戏关掉时不会发任何“我退出了”的消息,以前只能等心跳超时,**最长 35 秒后音乐才停**。现在程序每秒检查一次 `cs2.exe` 进程(用 psutil,`start.bat` 会自动安装):

- **游戏一退出,1 秒内停止音乐并重置状态**(测试中 0.5 秒),右上角提示「CS2 已退出」
- **游戏启动时自动定位安装目录**:就算启动时没找到 cfg 文件夹(装在非标准位置),也会从正在运行的 `cs2.exe` 路径找到它并写入 GSI 配置
- **提示是否需要重启 CS2**:如果 GSI 配置是在这次游戏启动之后才写入的,游戏读不到它,顶栏会显示红色「需要重启 CS2」;收到游戏数据后提示自动消失
- 顶栏状态:CS2 未运行 / CS2 已启动,等待数据 / 需要重启 CS2 / 主菜单 / 对局中比分和计时

检测的进程名在 `config.json` 的 `game_process_names` 里(默认 `cs2.exe` 和 Linux 版的 `cs2`)。没装 psutil 时自动退回到只靠 GSI 超时。

## 剪辑台:现场选片段、导出(v0.4 新增)

1. 在左侧曲库点一首歌(或把歌拖进导入区)。上方是整首概览,下方是可缩放的波形,带段落色带和节拍网格
2. **在波形上拖动**选出片段;拖选区边缘调整入点/出点,拖选区中间整体移动;单击设置光标
3. **吸附**:关 / 拍 / 小节。开着时,入点出点会自动对齐节拍,切出来的片段不会“抢拍”
4. 入点、出点可以直接输入(`1:05.2` 或 `65.2`),也可以用 ±0.1 秒、±1 拍按钮微调
5. 设好淡入、淡出和音量后:
   - **保存到曲库**:生成一个新的 WAV 文件放进曲库(重名会自动加序号)
   - **下载 WAV**:保存到你电脑的下载文件夹
   - **保存并使用**:保存后直接放到所选站点(从站点或 AI 推荐进入剪辑台时,会默认选好那个站点)

快捷键:`空格` 播放/停止选区,`I` / `O` 把光标设为入点/出点,`L` 循环,滚轮缩放,`Shift`+滚轮平移,`Esc` 停止所有声音。

**试听规则**:同一时间只有一个声音。开始任何试听(站点、AI 候选、剪辑台)都会先停掉其他正在响的,包括游戏引擎正在放的音乐;顶栏「停止」或 `Esc` 停止全部。

界面的设计思路见 `UI_DESIGN.md`。

## 社区:分享和导入音乐盒(v0.5 新增)

**分享的是“配方”,不是音频**:每个站点用哪首歌、从第几秒切、切多长、音量和淡入淡出,外加一串“声音指纹”(响度数字,无法还原成音乐)。服务器上不存任何音频文件,所以不会变成传播受版权保护歌曲的平台。

**使用**
1. 「设置 › 社区服务器」填服务器地址(服务器怎么搭见 `community/README.md`,**部署到 Render 免费版见 `community/RENDER.md`**;自己电脑上试用填 `127.0.0.1:8787`)
2. 「社区」页注册:邮箱 + 密码,注册后直接可用(不发验证邮件、不做两步验证)。**目前没有找回密码功能,请记住密码**
3. **分享**:点「分享当前音乐盒」→ 检查歌名、写标题和简介 → 发布。剪辑台导出的片段会自动还原成“原曲 + 起止时间”,别人才能用自己的歌重现
4. **导入**:点开任意一套 → 程序在你的曲库里找同一首歌:
   - **按声音指纹**:文件名完全不同、换了格式、前后多几秒都能认出来,并且**自动对齐时间差**(测试中误差约 1 毫秒)
   - **按歌名**:没有指纹时用歌名 + 时长
   - 找不到的歌可以手动选文件,或者先去剪辑台导入;缺歌的站点导入时会跳过
   - 导入前可以用自己的歌**试听每个站点**;导入后可以**撤销**
5. 也可以点赞、搜索(标题 / 歌名 / 标签 / 作者)、按最新或最热排序;自己分享的可以用当前音乐盒更新或删除;别人的可以举报

**免费服务器会休眠**:Render 等平台的免费服务闲置 15 分钟会休眠,下次访问约 1 分钟醒来。程序会自动处理:打开社区页时显示「社区服务器正在唤醒…」并等它醒来;操作中途碰上休眠会等醒了再自动重试(写操作如果已经发出、只是等回应超时,不会重复提交,而是提示你刷新确认)。

**隐私和安全**:登录令牌只保存在你电脑上的 `community_account.json`,不会发给网页;服务器只存密码的加盐哈希;别人看不到你的邮箱,也看不到你本地的文件名。公开的服务器请用 https,否则密码会明文传输(设置页会提示)。

## AI 分析:自动挑片段(v0.2 新增)

把几首歌导入音乐库,在面板「AI 分析」里点 **开始分析**,程序会:

1. 画出每首歌的**段落结构**(前奏 Intro / 主歌 Verse / 铺垫 Build-up / 高潮 Chorus·Drop / 间奏 Breakdown / 尾奏 Outro)和能量曲线
2. 为每个事件给出 **3 个候选片段**(哪首歌、从第几秒切、切多长)、匹配度分数和理由
3. 每个候选都能 **▶ 试听**;满意就点 **采用**(或「全部采用第一推荐」),也可以点 ✂ 带着这个区间去剪辑台精修

### 原理(音乐信息检索 MIR, Music Information Retrieval)

- **特征提取 Feature Extraction**:每 0.1 秒计算响度 Loudness(按 0.4 秒窗口平滑)、低频能量 Low-end(底鼓 + 贝斯)、鼓点密度 Onset Density、明亮度 Spectral Centroid、和声色彩 Chroma(估计大调/小调 → 情绪明暗)
- **节拍追踪 Beat Tracking**:找到小节第一拍 Downbeat(结合底鼓、起音和和弦变化),所有片段都从小节线切入
- **结构分析 Structure Segmentation**:自相似矩阵 Self-Similarity Matrix + 新颖度曲线 Novelty Curve 找段落边界
- **事件画像 Event Profiling**:每个事件有一个“理想片段”画像,对所有候选窗口打分,例如:
  - MVP:高能量 + 处在副歌/高潮 + 开头有冲击(低频回归)
  - 回合/炸弹剩余10秒:能量持续上升 + **结尾正好进入高潮**(铺垫段的最后 10 秒)
  - 炸弹已安放:紧张(有节奏推动的中高能量)、偏暗;如果能**与「炸弹剩余10秒」首尾相接**会加分 —— 30 秒 + 10 秒正好等于 40 秒炸弹时间,音乐不断,炸弹爆炸那一刻正好进入高潮
  - 阵亡:安静、鼓点稀疏、没有突兀冲击;回合失败:能量偏低、回落、偏暗
  - 主菜单 / 热身:**可无缝循环**(片段结束后的那一小节和开头那一小节听起来一样)
- 多首歌一起比较,并尽量让不同事件用不同段落(重要事件先挑)

分析结果缓存在 `analysis_cache/`,同一首歌第二次分析不到 1 秒。改了事件时长后点「重新分析」即可按新时长推荐。

### 说明

- 这是基于音频特征的算法分析,不是“听懂”歌曲的大模型:它擅长找结构、能量、节奏和冲击点,**不理解歌词和风格语义**。推荐请当作起点,以耳朵为准。
- 结构清楚的歌(流行、EDM、摇滚、游戏 OST)效果最好;全程平稳的氛围音乐,各段差别小,推荐也会比较接近。
- 显示的 BPM 偶尔是实际速度的一半或两倍(常见的倍速歧义),不影响切点:片段仍然对齐小节线。
- 用合成测试曲做了回归测试(`python test_analyzer.py`):段落边界误差约 0.02 秒,MVP 落在高潮开头,两个倒计时都正好结束在高潮开始处。真实歌曲的效果需要你试听验证。

## 支持的事件

| 事件 | 触发条件 | 精度 |
|---|---|---|
| 主菜单 Main Menu | 游戏回到主菜单(GSI 数据里没有 `map`) | 准确 |
| 热身 Warmup | `map.phase` 变为 `warmup` | 准确 |
| 回合开始 Freeze Time | `round.phase` 变为 `freezetime`(购买阶段) | 准确 |
| 行动开始 Round Live | 冻结时间结束 | 准确 |
| 阵亡 Death Cam | 自己血量变 0,或观察对象切到队友 | 准确 |
| 回合剩余10秒 | 回合开始时间 + 回合时长 − 10 秒 | **估算** |
| 炸弹已安放 Bomb Planted | `round.bomb` 变为 `planted` | 准确 |
| 炸弹剩余10秒 | 安放时间 + 40 秒 − 10 秒 | **估算** |
| 回合胜利 / 失败 | `round.win_team` 与我方阵营比较 | 准确 |
| MVP 主题曲 MVP Anthem | 自己的 `mvps` 数增加 | 见限制 |
| 比赛胜利 / 失败 | 比赛结束时比较双方比分 | 准确(平局不播) |

**优先级规则**:同一时间触发多个事件,只播优先级最高且配了曲目的那个(例如拆包胜利同时拿 MVP → 播 MVP)。低优先级事件不会打断正在播放的高优先级音乐(例如炸弹音乐播放中你阵亡,炸弹音乐继续)。「主菜单 / 热身 / 回合开始 / 比赛结束」是重置型事件,总会切换;没配曲目时会停掉上一首。优先级可在面板里改。

## 已知限制(诚实说明)

- **只有你自己听得到**。真正的音乐盒 MVP 主题曲全服可听,这个做不到(别人的客户端播放的是他们自己的文件)。
- **“剩余10秒”是估算**:以玩家身份游戏时,GSI 不提供倒计时(`phase_countdowns` 只对 GOTV/观战者开放,Valve 文档有说明),所以按回合开始/下包时间自己计时,误差取决于 GSI 推送延迟(配置里已把缓冲设为 0、节流 0.1 秒),实际误差请以实测为准。回合时长按模式默认值:竞技 115s、休闲 135s、搭档(scrimcomp2v2)90s;如果不准,在「设置」页的「计时」里改,或调整「延迟补偿」。
- **程序中途启动**时,当前回合不会有“剩余10秒”提示(不知道回合何时开始),下一回合恢复。
- **MVP**:阵亡后 GSI 的 `player` 字段会变成你正在观战的队友,看不到自己的 MVP 数。所以**阵亡状态下拿到的 MVP 可能检测不到**(存活时拿到的可以)。
- 模式名(competitive / casual / scrimcomp2v2 …)沿用 CS:GO 时代的 GSI 命名;如果 CS2 的实际名字不同,面板「游戏状态 > 模式」会显示真实值,在 `config.json` 的 `round_time` 里加上即可。

## 合规

只读取 Valve 官方 GSI 推送的数据(都是你自己屏幕上已有的信息),不修改 VPK、不读内存、不注入,也不向游戏发送任何输入。不影响进入官方服务器(sv_pure)。

## 常见问题

- **顶栏一直显示「CS2 已启动,等待数据」**:游戏还在加载时这是正常的;进了主菜单还这样,去「设置」看 GSI 配置是否写入成功、写入后有没有重启过 CS2。
- **顶栏显示「需要重启 CS2」**:配置是在游戏开着的时候写入的,关掉 CS2 再打开一次即可。
- **端口被占用**:改 `config.json` 里的 `port`,重新运行,程序会自动更新 GSI 配置(之后要重启 CS2)。
- **社区里导入后时间不准**:在导入面板里手动调“时间偏移”(正数 = 往后推)。指纹对齐依赖分析库 librosa,没装时只能按歌名匹配、偏移为 0。
- **从 v0.3 升级过来**:v0.4 基于 v0.2,不含预训练模型 CLAP。可以删掉旧的 `clap_ai.py`、`install_ai_model.bat` 和 `analysis_cache` 里的 `clap_*.npy`;`config.json` 里的 `ai_model` 会被忽略。
- **AI 分析提示缺少依赖**:源码版在程序文件夹运行 `pip install librosa`(`start.bat` 会自动安装,首次几分钟);exe 版已经自带。第一次分析会多花十几秒(在编译加速代码)。
- **队友说听不到音乐**:看「队友语音」页状态是不是「正在运行」、那个站点有没有选中;Steam 的语音输入设备是不是 CABLE Output;说话键有没有按住
- **队友说听到回声或重复的声音**:麦克风是不是选成了虚拟设备;Windows 默认播放设备是不是被设成了 CABLE Input;是不是用了外放
- **「队友语音」页说缺少音频组件**:源码版运行 `pip install sounddevice`(`start.bat` 会自动安装);exe 版已经自带
- **pygame 安装失败**:`requirements.txt` 用的是 `pygame-ce`(社区维护版,新 Python 支持更快)。如果你已经装过原版 `pygame` 2.1+,也能直接用;两者不要同时安装。
- **音量**:顶部「总音量」× 每个事件的音量。
